# On-Chain Proof Guide

Every AI recommendation generated by YieldSage is cryptographically committed to the
Mantle blockchain as a verifiable, tamper-proof record.

---

## Why On-Chain Proof Matters

AI recommendation systems can be edited after the fact. By committing a SHA-256
fingerprint of every recommendation to an immutable Mantle transaction, YieldSage
guarantees:

1. **Immutability** — The recommendation payload cannot be altered retroactively.
2. **Auditability** — Anyone can inspect the public Mantle transaction and recompute the
   hash to confirm it matches.
3. **Trust without a central server** — Verification is done client-side using the Web
   Crypto API, with no requirement to trust the YieldSage backend.

---

## How the Commitment Is Created

### Step 1 — Canonical Payload

YieldSage constructs a deterministic JSON object from the recommendation batch:

```json
{
  "timestamp": "2026-06-20T14:00:00Z",
  "protocol_id": "uuid-of-protocol",
  "risk_tag": "moderate",
  "rank": 1,
  "apy_at_time": 24.55,
  "ai_reasoning": "Agni Finance USDC/USDT offers...",
  "ai_model": "cerebras/gpt-oss-120b"
}
```

Keys are sorted alphabetically and no extra whitespace is added, ensuring the string is
identical every time regardless of serialisation library.

### Step 2 — SHA-256 Hash

```python
import hashlib, json
payload_str = json.dumps(canonical_payload, sort_keys=True, separators=(',', ':'))
hash_hex = hashlib.sha256(payload_str.encode('utf-8')).hexdigest()
# e.g. "956988089b6b61a42d5c8238c40fb07db3205ed373283801ba28151f22b98f16"
```

### Step 3 — Mantle Transaction

The hash is embedded in the `data` field of a 0-MNT self-transaction:

```
data: "yieldsage:<hash_hex>"
from: 0x<YieldSage agent wallet>
to:   0x<YieldSage agent wallet>
value: 0
```

The resulting Mantle transaction hash (e.g. `0x956988...`) is stored in the
`recommendations.on_chain_tx_hash` database column.

## How to Verify

### Option A — YieldSage Verification Page (browser)

Navigate to:
```
https://yieldsageai.xyz/verify?tx=<on_chain_tx_hash>
```

The page:
1. Fetches the recommendation from the YieldSage database
2. Reconstructs the canonical JSON payload
3. Recomputes the SHA-256 using the browser's Web Crypto API (no server trust)
4. Compares against the on-chain record
5. Displays ✅ **Perfect Match** or ❌ **Hash Mismatch — Tampered!**

### Option B — YieldSage API (programmatic)

```
GET https://api.yieldsageai.xyz/api/recommendations/verify/{tx_hash}
```

Returns `{ "verified": true, "match": true, "recommendation_hash": "...", ... }`

### Option C — Manual on-chain inspection

1. Open `https://mantlescan.xyz/tx/<on_chain_tx_hash>`
2. Find the **Input Data** field and decode it as UTF-8 text
3. You will see: `yieldsage:<hash_hex>`
4. Independently fetch the recommendation from the YieldSage API and recompute the hash
5. Confirm the two hashes match

## Skill Usage Notes

- When presenting any recommendation, always include the `on_chain_tx_hash` and the
  Mantlescan URL.
- When a user provides a TX hash for verification, always call the
  `/api/recommendations/verify/{tx_hash}` endpoint — never compute or assert a
  verification result from memory.
- If `on_chain_tx_hash` is `null`, inform the user that the on-chain commit is pending
  (YieldSage retries failed commits on a 6-hour background cycle).
